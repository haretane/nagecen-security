# NAGeCen Security

NAGeCenに投稿するWebサービスを対象とした、初心者向けセキュリティ診断サービスです。

現在は、診断候補URLの安全確認、metaタグによるサイト所有確認、OWASP ZAPによる段階別診断のジョブ実行基盤を実装しています。

今後の検討事項として、本番公開前に診断範囲、誤検出・見逃し、結果の利用方法などを説明する利用規約と免責表示を整備します。

Lv.1（`basic`・無料）はパッシブ診断だけを行い、入力欄へテスト文字を送信しません。XSSは未診断であることを結果に明示します。

Lv.2（`xss`・無料）はLv.1に反射型XSSルール（40012）を追加します。保存型XSSはデータを作成・変更する可能性が高いため、MVPでは実行しません。

Lv.3（`advanced`・有料）はLv.2に、SQLインジェクション（40018）、OSコマンドインジェクション（90020）、パストラバーサル（6）を追加します。その他のActive Scanルールは無効のままです。決済と利用制限が未実装の間は準備中として、画面とAPIの両方で開始を拒否します。

## 必要なもの

- Docker Desktop
- Git

## 起動方法

```bash
docker compose up --build
```

起動後、以下を確認します。

- 画面: http://localhost:5174
- APIの動作確認: http://localhost:8000/health
- APIドキュメント: http://localhost:8000/docs
- PostgreSQL（ローカルDBクライアント用）: 127.0.0.1:5433

画面に「開発環境は正常です」と表示されれば、フロントエンドからバックエンドとデータベースまで接続できています。

画面のURL入力欄では、公開WebサイトのURLだけを受け付けます。URLの安全確認だけでは対象サイトへアクセスしません。

所有確認キーを発行した後、表示されたmetaタグを対象ページの`<head>`内へ設置して「設置したmetaタグを確認」を押すと、対象ページへ安全対策付きでアクセスしてタグを照合します。

- 確認キーの有効期限は30分です。
- 確認キーはデータベースへ平文保存せず、ハッシュ化して保存します。
- リダイレクト先は毎回URLとIPを再検査します。
- 最初に指定したプロダクトのURL範囲以外には移動しません。
- 取得するHTMLは最大1MB、通信時間は最大10秒です。

所有確認では、確認キーを発行した記録（`verification_challenges`）と、実際に確認できた対象（`verified_targets`）を分けて保存します。

確認済みの範囲は、次の2つの組み合わせです。

- origin: 通信方式・ホスト名・ポート番号（例: `https://ucu4.sakura.ne.jp`）
- base path: そのプロダクトが置かれたパス（例: `/app-a/`）

同じホスト上の`/app-b/`は別の範囲として扱います。所有確認や診断中のリダイレクトでも、この範囲を越えて自動的に許可しません。

### 今後の対応候補：Google Apps Script（GAS）

GASで公開したWebアプリのように、URLのパスが`/macros/s/.../exec`など長くなること自体は現在の仕組みで扱えます。一方、GASではアクセス時に`script.google.com`から`script.googleusercontent.com`など別ホストへ正規にリダイレクトされる場合があります。

現在の所有確認は、第三者サイトへのすり替えを防ぐため、別ホストへのリダイレクトを拒否します。そのため、GASの所有確認・診断は正常に完了しない可能性があります。

対応する場合もGoogle関連ホストを無条件に許可せず、次を検証するGAS専用方式を設計します。

- 入力URLが正式なGAS公開URLか
- リダイレクト先が想定したGoogleの正規ホストか
- 想定したリダイレクト経路か
- 最終ページに今回発行した確認タグがあるか
- 所有確認後の診断範囲をどのURLに固定するか

本番公開前の互換性確認項目として扱います。

## Lv.1診断の構成

所有確認が成功し、診断許可への同意が行われた場合だけ診断ジョブを作成します。

Active Scanを含む場合は、診断許可に加えて、テスト用リクエストの送信とデータ変更リスクへの個別同意を必須にします。

- APIは診断ジョブをPostgreSQLへ登録します。
- 外部公開ポートを持たない専用Workerが待機ジョブを取得します。
- Workerがジョブごとに一時的なZAPコンテナを起動します。
- ZAPは内部Dockerネットワークだけに接続し、対象ホスト限定の出口Proxyを経由します。
- 出口Proxyは接続ごとにDNS解決後のIPを検査します。
- 診断ジョブには、開始時点のoriginとbase pathをコピーして記録します。
- ZAPのAutomation Planに確認済みbase pathのContextを設定し、巡回対象を限定します。
- 保存前にもレポートを確認し、確認済みのURL範囲外にある結果を除外します。
- ZAPと出口Proxyはジョブ終了後に削除します。
- ZAPにはCPU、メモリ、プロセス数、実行時間の上限を設定します。
- Spiderは深さ3階層、各ページから最大20件、同時2通信に制限し、フォームを自動送信しません。robots.txtとサイトマップからの大量URL追加も無効にします。
- 開始待ち・実行中の診断は全体で最大10件までとし、それ以上の予約は完了を待つよう案内します。
- Lv.2のXSS Active Scanは1スレッド、リクエスト間隔250ms、ルール最長2分、全体最長3分、最大10アラートに制限します。
- Lv.3 Active Scanは1スレッド、リクエスト間隔500ms、各ルール最長2分、全体最長6分、各ルール最大10アラートに制限します。

Workerだけは一時コンテナを作成するためDockerソケットを使用します。Web APIにはDockerソケットを渡していません。

## ログインが必要なページの問診

診断開始前に、ログインが不要か、通常のID・メールアドレス＋パスワード方式か、外部認証・特殊認証かを選びます。

通常ログインを選ぶと、ログインURL、ID・メールアドレス、パスワードの入力欄を表示します。ZAPのヘッドレスブラウザ（画面を表示せず自動操作するブラウザ）が一般的なログインフォームを自動判定します。ログイン成功を確認できた場合だけ、その利用者としてSpiderとActive Scanを実行します。認証に失敗した場合は認証なしの診断をやり直し、公開ページの結果を保存します。Google・GitHub・Appleなどの外部認証と特殊認証はMVP対象外です。

診断ジョブへ保存するのは認証方式と実行状態だけです。パスワードは診断ジョブ作成APIでも受け付けません。

APIとWorkerの間には専用の一時保管領域を用意しています。この領域は外部ポートを持たず、ディスクへの永続保存を無効化し、認証情報に15分の有効期限を設定します。Workerが取得すると同時に削除される一度限りの受け渡しです。ログインURLはSSRF対策を通し、所有確認済みのoriginとbase pathの範囲内だけを受け付けます。認証情報を含むZAPの一時設定と診断コンテナも、処理後に破棄します。

## 結果の重要度

ZAPの検出結果は、NAGeCen Securityの画面で次のように案内します。

- High: 高（最優先で確認）
- Medium: 中（優先して確認）
- Low: 低（余裕があれば改善）
- Informational: 参考（参考情報）

重要度は「攻撃された」「脆弱性が確定した」という意味ではありません。機械的な診断には誤検出や、サイトの用途によって対応不要となる項目もあるため、初心者向け説明とZAPの技術名を両方保存・表示します。

## 自動テスト

```bash
docker compose exec backend pytest -q
```

localhost、内部ネットワーク、認証情報付きURL、規定外ポート、危険なリダイレクトなどが拒否されることを確認します。

## 停止方法

起動中のターミナルで `Ctrl + C` を押した後、以下を実行します。

```bash
docker compose down
```

データベースの保存内容も削除して完全に初期化する場合だけ、次を使用します。

```bash
docker compose down --volumes
```

## 環境設定

通常のローカル確認では設定ファイルを作らなくても起動できます。値を変更したい場合は、`.env.example` を `.env` という名前でコピーして編集します。

`.env` はパスワードなどを含む可能性があるため、Gitには登録されません。

ローカル開発では、Security APIのCORSに以下の画面を許可しています。

- NAGeCen Security: `http://localhost:5174`
- NAGeCen本体: `http://localhost:5173`

CORSは、異なるポートの画面からAPIへ接続してよいかをブラウザへ伝える設定です。パスは含めないため、NAGeCen本体が`/nagecen/`配下にあっても許可値は`http://localhost:5173`です。

## NAGeCen本体との連携

NAGeCen本体のPHPサーバーは、署名付きJSONを`POST /api/integrations/nagecen/handoffs`へ送ります。SecurityはHMAC-SHA256署名、5分の期限、jti、プロダクトIDとURLを検証し、10分だけ有効な一度限りのhandoff tokenを返します。

Security画面はtokenを交換するとURLから削除し、60分有効のHttpOnly Cookieで連携状態を再開します。所有確認・診断結果はWebhook outboxへ保存し、NAGeCen本体へ方向別の秘密鍵で署名して通知します。通知失敗時は10秒、1分、5分、30分後に再送し、初回を含め最大5回試行します。

秘密鍵は`.env`だけへ設定し、フロントエンドや`VITE_`変数へ入れません。

## Database Client JDBCから接続する

VS CodeのDatabase Client JDBCなどから、以下の内容で接続できます。

- 種類: PostgreSQL
- Host: `127.0.0.1`
- Port: `5433`
- Database: `nagecen_security`
- User: `nagecen_security`
- Password: `change-me-for-local-development`
- JDBC URL: `jdbc:postgresql://127.0.0.1:5433/nagecen_security`

DBポートはMac内の`127.0.0.1`だけに公開しており、外部ネットワークからは接続できません。
