# 提出・デモ用プレビューモード

ローカルトップの「プレビューモード」または `http://localhost:5174/preview/demo` から開始できます。

実通信用の DiagnosticPreparation / DiagnosticExecution / DiagnosticResults を共用し、クライアントだけメモリ内の模擬実装に差し替えています。ログインの認証連携そのものは模擬せず、「プレビュー利用者」と明示します。

1. 準備の注意事項を確認し、チェックを入れてURL入力へ進む。
2. `https://test.example.com/` などの表示用URLを入力する。実際にはアクセスしない。
3. タグのコピーと確認ボタンを操作する。実際のタグ設置は不要。
4. 基本チェック／反射型XSS追加を選び、実行前の確認へ進む。
5. 同意して開始すると、待機 → 実行 → サンプル結果が約10〜15秒で表示される。

外部通信・診断API・Cookie認証・DB保存・利用回数消費は行いません。入力した認証情報を送信・保存しませんが、実際の秘密情報は入力しないでください。再読み込みすると最初に戻ります。結果・AIプロンプトにも架空のサンプルである旨を表示します。

提出時の `/check` はログイン後に停止案内と仕組みの説明を表示します。実通信用の認証・ランダムタグ発行・対象ページからのタグ確認・ジョブ登録・ポーリング・実結果表示のコードは削除していません。デモのためにWorkerは起動しません。

停止は初期値です。backendは `SECURITY_DIAGNOSTICS_PAUSED` が明示的に `false` でない限り、URL確認・タグ発行／確認・ジョブ作成・既存プロダクトhandoff作成／交換を503で拒否します。Workerも新たなジョブを取得しません。ログインAPI、既存結果の読み取り、中止処理は停止対象から除外しています。
画面側も `VITE_SECURITY_DIAGNOSTICS_PAUSED=false` でない限り実診断画面を表示しません。利用条件確認前には再開しないでください。本番へのデプロイは今回行っていません。

本体側への伝言：卒業制作の提出時は、本体の投稿ページ・マイページ・バナーなどからSecurityへの診断導線を非表示にしてください。Securityからのアカウントログイン連携と `/nagecen/security-login` は残してください。APIやDBを削除する必要はありません。本体側コードはこのリポジトリから変更していません。

開発時は有効です。提出用の静的ビルドは frontend で `npm run build:demo` を実行すると `frontend/dist-demo/` に作成されます。通常の `frontend/dist/` とは分けています。静的配信する場合は `/preview/demo` を index.html にフォールバックする設定が必要です。通常のビルドではこの入口を無効化します。本番の認証設定やデプロイは変更しません。

固定タグの再利用は通常の発行処理・Compose設定から除去済みです。通常タグは発行ごとにランダム生成され、現在の確認期限は30分です。DBの一意制約は維持しています。
