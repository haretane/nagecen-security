# ローカル診断準備画面の接続（2026-10-06）

## 範囲

新認証が有効な開発環境の `/check` を、`DiagnosticPreparation.jsx` の準備画面と
`DiagnosticExecution.jsx` の診断設定・実行画面へ接続しました。
既存の表示専用 `/preview/diagnostic-wizard` は通信しないまま残しています。
本番ビルドの認証フラグ・旧診断画面・DB定義・本番設定は変更していません。
結果APIにはZAPの確信度に基づく `confidence_label` を追加しました。

- テスト環境の準備確認
- URL形式・公開接続先IPの検証、確認タグの発行
- タグのコピー、対象HTMLの取得とタグの設置確認
- 確認済み対象IDを保持した診断内容選択、ログイン設定、実行前の明示同意
- 明示操作による診断依頼、状況取得、待機中の中止、実データの結果・AIプロンプト表示

準備・設定だけでは診断APIを呼びません。同意して「診断を開始する」を押したときだけ依頼します。
Workerは自動起動しません。Worker停止中は依頼しても待機状態のままです。
基本チェックと反射型XSSだけを選択できます。保存型・DOM型XSS・SQL確認は準備中です。
フォームログイン情報は明示実行時のみAPIへ送信し、既存RedisのTTL付き一時保管を使用します。
ブラウザの永続ストレージへ保存せず、依頼成功・ログイン対象解除・画面離脱で入力状態を破棄します。
月5回等の利用回数・課金の制御はまだありません。
URL検証APIはページを取得しないため、404・403・BOT対策の事前判定を装いません。
期限はバックエンドが返す `expires_at` を使用します。現行バックエンドは30分で、プレビューの60分とは異なります。

## 中断と再試行

- タグ未検出 (`meta_not_found`) のみ、20秒後に一度自動再確認します。
- ネットワークエラー、429、期限切れ等では自動再試行しません。
- 連打は操作中フラグで防ぎ、戻る・ログアウトによるアンマウント時は要求／再試行待ちを中止します。
- URLを送信し直す際には前の確認情報を破棄し、新しいタグを発行します。
- 401は既存のセッション失効処理へ引き継ぎます。
- タグ／確認先IDは画面のメモリ内だけに保持し、localStorage等には保存しません。
- 再読み込みではログインをサーバーへ再確認しますが、準備途中の情報は復元せず最初からです。
  依頼成功後だけ `/check?job={id}` に切り替わり、このURLでは当該アカウントの状況・結果を再取得します。
  通常の `/check` に過去の診断を自動表示しません。アカウントをまたぐアクセスは既存APIが拒否します。
- 開始要求の通信エラーは自動再送しません。受付済みの可能性を説明し、再操作には再同意が必要です。
- 状況取得は5秒間隔の直列処理です。終了時・画面離脱で停止します。取得エラーは再確認ボタンで再開します。
- Abort後も既にサーバーが処理した発行／確認を取り消せるわけではありません。現段階では確認情報の再取得・再開APIは追加していません。

- 実サイトへのHTTP取得や実際のタグ設置確認は、利用者がテストURLを指定して行う次の手動確認です。今回の自動テストでは実APIを呼びません。

## 次の段階

### 通常のタグ発行への復帰

固定タグの再利用処理と専用設定ファイルを除去しました。
タグは毎回ランダム発行され、対象サイトのHTML取得と照合が必要です。
確認期限30分、回数制限、DBの一意制約は維持しています。
ローカルbackendは既存認証設定を保持したままrestartしてください。
操作デモには外部通信なしの `/preview/demo` を使用できます。
詳しくは [preview-demo.md](preview-demo.md) を参照してください。

画面確認だけを先に進める場合は、開発環境の
`/preview/diagnostic-wizard?start=options` を利用できます。
準備画面にも「タグ設置を省いて診断内容の選択から進む」リンクを追加しています。
`url` クエリで表示対象URLを引き継ぎますが、通信・タグ確認・実際の診断は行いません。
既存タグの固定化や実APIの権限確認の省略はせず、本番ビルドではこの入口を無効にします。

次はWorker起動と、利用者が明示同意したテストサイトでの実診断を確認します。
履歴一覧、期限60分化、利用回数制限等は今回の範囲外です。
