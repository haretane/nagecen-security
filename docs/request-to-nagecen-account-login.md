## 希望する流れ

```text
Securityトップ
→ NAGeCenのSecurity専用入口
→ 未ログインなら既存のログイン／新規登録
→ 利用するアカウントを確認してSecurityへ進む
→ Securityの診断準備・テストURL入力
```

- 本体にプロダクトを登録していない利用者も利用できます。下書き・仮プロダクトの作成は不要です。
- 対象URLはSecurity側で入力します。テストURLを使ってもらいます。
- 対象サイトへ確認タグを設置できることはSecurity側で確認します。作者本人や本体プロダクトの所有者照合とは別です。
- バッジ、料金、回数の具体的な上限、本体との診断結果再連携は今回は実装しません。

## 本体側で検討してほしい追加範囲

1. 新規 `/nagecen/security-login` 入口。既存ProtectedRoute／Loginの「ログイン前の画面へ戻る」仕組みを活かし、新規登録後も戻れること。
2. 有効なPHPログインセッション＋CSRFを検証する、専用の確認コード発行API。
3. Securityサーバーだけが署名付きで呼ぶ、確認コード交換API。
4. 短時間・一度限りのコード、PKCE challenge、利用者IDなどを保存するDB追加と非破壊の移行。
5. callbackの完全一致固定、ログへの秘密情報非出力、認証用途専用の設定・鍵。

名称・JSON・署名対象・期限・エラーの詳細は上記仕様案にあります。
コード発行では、利用者IDをリクエストから信用せず、PHPセッションと有効なusersレコードから取得してください。
現状の本体users.idを安定した識別子として使えるか、削除後に別人へ再割当てされないかも確認をお願いします。

既存の `create_security_handoff.php` と `/api/integrations/nagecen/handoffs` はプロダクト連携用です。
